## 📋 速览

C 程序的抽象状态机由值、类型和二进制表示三层构成。基本类型由关键字提供（有 Rank 和四种数据模型），语义类型（size_t、uint32_t 等）由标准库 typedef 提供，是编写可移植代码的起点。窄类型（Rank < 3）参与运算前自动提升为 int，字面量按进制和后缀推导类型（四条规则），浮点字面量默认 double 且存在精度陷阱——十六进制浮点解决精确表示问题。隐式转换遵循 Rank 和符号性规则：同符号按等级升高，混合符号有平台依赖性。初始化器从标量直接赋值到数组指定初始化，C23 引入通用 {}。

## 📖 知识点

### 知识点 1：抽象状态机

**是什么**

程序文本描述了一个**抽象状态机**，它规定了程序如何从一种状态转移到下一种状态。这些状态由值、类型和二进制表示决定。

**详细解释**

从三个核心概念开始

| 概念                                | 解释                                                         |
| ----------------------------------- | ------------------------------------------------------------ |
| 值（value）                         | 抽象的数学实体（只是一种概念）                               |
| 类型（type）                        | 附加在值上的属性（值的范围、能做那些运算）                   |
| 二进制表示（binary representation） | 桥接类型和值的数学公式（如何用位模式描述值，依赖平台特征值） |
| 对象表示（object representation）    | 内存中实际存储的位模式（平台相关）                           |

> [!TIP]
>
> 值和值的表示是两回事：例如数值 $12$，可以表示成阿拉伯数字 $12$、罗马数字 $XII$、英文 twelve。表示方式不同，但值本身不变
>
> 计算机也是一样的。同一个值，不同的类型下，二进制表示可能完全不同。学习 C 语言和核心原则：**C 程序关注的值而不是其表示**

+ 值是一种抽象数学实体，独立于任何计算机存在；C 程序的语义都是围绕值展开的。

+ 类型附加在值上属性，它决定了：（1）值的范围，（2）能做那些运算。例如，对于值 $255$，如果存储在类型是 `unsigned char` 对象中就是合法的；如果存储在 `signed char` 对象中，就会溢出。

+ 二进制表示也是一种抽象概念：在数学上，规定了如何用位模式表示特定类型的值。例如，无符号整数
    $$
    \text{value} = \sum_{i=0}^{n-1} \text{bit}_i \times 2^i
    $$
    在任何平台上，这个公式都是通用的；只是这个 $n$ 在不同的平台上可能不同，它称为平台的特征值。

+ 对象表示是内存中实际是如何存储位模式。涉及字节序、对齐填充等概念。与平台相关

> 想要写出可移植的代码，就不要去想那些平台细节：例如，这个整数在内存里是几个字节、什么字节序（对象表示）。甚至是不需要去关注二进制表示

C 标准规定了每种类型应该使用怎样的二进制表示以及与平台相关的特征值；只要知道了操作数的值以及平台相关的特征值，操作的结果就是可推断的。例如，对于 `size_t` 类型的操作，需要检查操作数和 `SIZE_WIDTH`（表示 `size_t` 类型位模式长度）特征值，就可以完全确定

**优化**：编译器只需要保证程序的**可观察行为**不变，编译器可以任意调整我们的代码。C 标准规定了几个不能进行优化的事实：(1) `volatile` 访问，（2）文件 I/O，（3）交互式 I/O。其他全是可优化的空间。

**代码示例**

编译器优化示例

```c
size_t a = 45;
size_t b = 7;
size_t c = (a - b) * 2;
printf("c is %zu\n", c);
```

编译器发现 `a` `b` `c` 后面不再使用，可以在编译时计算出 `c = 76`，根本不给 `a` 和 `b` 分配内容；甚至更狠一点，直接输出 `"c is 76\n"`

### 知识点 2：基本类型

**是什么**

C 的基本类型由两部分组成，分别由 **关键字** 和 **头文件**（语义类型） 提供。根据基本类型还可以派生出其他类型

**详细解释**

下表列出了由关键字提供的基本类型

| 类别           | 系统名称             | Rank | 类别              | 系统名称               | Rank |
| -------------- | -------------------- | ---- | ----------------- | ---------------------- | ---- |
| **无符号整数** | `bool`               | 0    | **有/无符号整数** | `char`                 | 1    |
|                | `unsigned char`      | 1    | **有符号整数**    | `signed char`          | 1    |
|                | `unsigned short`     | 2    |                   | `signed short`         | 2    |
|                | `unsigned int`       | 3    |                   | `signed int`           | 3    |
|                | `unsigned long`      | 4    |                   | `signed long`          | 4    |
|                | `unsigned long long` | 5    |                   | `signed long long`     | 5    |
| **实浮点数**   | `float`              |      | **复浮点数**      | `float _Complex`       |      |
|                | `double`             |      |                   | `double _Complex`      |      |
|                | `long double`        |      |                   | `long double _Complex` |      |

C 标准为每种 Rank 整数类型规定了最小宽度。下表列出了每个 Rank 的 C 标准规定的最小尺寸以及具体实现选择的具体尺寸。

| Rand | C 标准(位) | LP32(位) | ILP32(位) | LLP64(位) | LP64(位) |
| ---- | ---------- | -------- | --------- | --------- | -------- |
| 1    | $\ge 8$    | $8$      | $8$       | $8$       | $8$      |
| 2    | $\ge 16$   | $16$     | $16$      | $16$      | $16$     |
| 3    | $\ge 16$   | $16$     | $32$      | $32$      | $32$     |
| 4    | $\ge 32$   | $32$     | $32$      | $32$      | $64$     |
| 5    | $\ge 64$   | $64$     | $64$      | $64$      | $64$     |

具体实现对基本类型大小的选择称为数据模型，被广泛接收的由 $4$ 种

| 模型      | int  | long   | pointer | 典型平台                |
| --------- | ---- | ------ | ------- | ----------------------- |
| **LP32**  | 16   | 32     | 32      | Win16 API               |
| **ILP32** | 32   | 32     | 32      | Win32、32位 Linux/macOS |
| **LLP64** | 32   | 32     | 64      | Win64 API               |
| **LP64**  | 32   | **64** | 64      | 64位 Linux/macOS        |

> 虽然 `bool`（Rank 为 $0$）只需要 $1$ 位就可以完全表示，但是计算机访问内存的最小单元就是字节($8$位)。因此，`bool` 类型在大多数具体平台上都是 $8$ 位
>

> [!WARNING]
>
> **不追求"精确宽度"**。C 标准只规定了基本类型最小宽度，不规定精确宽度。精确宽度由具体实现定义，不同的实现可能会选择不同的宽度

**浮点类型**：C 标准并未规定浮点数类型应该采用怎样的浮点格式，只是说明了如果平台支持 IEEE-754 浮点格式就采用该格式

| 类型          | 格式               | 典型大小 |
| ------------- | ------------------ | -------- |
| `float`       | IEEE-754 binary32  | 32 bit   |
| `double`      | IEEE-754 binary64  | 64 bit   |
| `long double` | IEEE-754 binary128 | 128 bit  |

> [!TIP]
>
> 无论如何，浮点类型能够表示值的范围应该远大于整数类型

**代码示例**

```c
/* basic_types.c — 查看当前平台的基本类型宽度 */
#include <stdio.h>
#include <stdint.h>

int main(void) {
    printf("=== 当前平台数据模型 ===\n");
    printf("char      : %2zu 字节\n", sizeof(char));
    printf("short     : %2zu 字节\n", sizeof(short));
    printf("int       : %2zu 字节\n", sizeof(int));
    printf("long      : %2zu 字节\n", sizeof(long));
    printf("long long : %2zu 字节\n", sizeof(long long));
    printf("指针      : %2zu 字节\n", sizeof(void*));
    // 根据 int=4, long=8, 指针=8 → LP64 模型
}
```

### 知识点 3：语义类型

**是什么**

语义类型是标准库通过 `typedef` 定义的类型，它们的名字暗示了该类型的用途

**详细解释**

恰好必须使用 $32$ 位无符号整数时，就应该使用 `uint32_t`（来自头文件 `<stdint.h>`）的语义类型，而不是使用 `unsigned int`。使用语义类型（例如，`size_t` `uint32_t`）是编写可移植程序的起点。下表列出了常用的几种语义类型

| 类型        | 头文件       | 含义                    | 典型用途                  |
| ----------- | ------------ | ----------------------- | ------------------------- |
| `size_t`    | `<stddef.h>` | 大小、基数              | `sizeof` 返回值、数组下标 |
| `ptrdiff_t` | `<stddef.h>` | 指针差值                | 两个指针相减              |
| `uintmax_t` | `<stdint.h>` | 最大宽度无符号整数      | 预处理器算术              |
| `uint{N}_t` | `<stdint.h>` | 宽度为 `N` 的无符号整数 | 预处理器算术              |
| `intmax_t`  | `<stdint.h>` | 最大宽度有符号整数      | 预处理器算术              |
| `int{N}_t`  | `<stdint.h>` | 宽度为 `N` 的有符号整数 | 预处理器算术              |
| `time_t`    | `<time.h>`   | 日历时间（秒）          | `time(0)` 返回值          |
| `clock_t`   | `<time.h>`   | 处理器时间              | `clock()` 返回值          |

> 类型 `time_t` 和 `clock_t` 用于时间处理。它们的具体精度因平台而异，所以它们是"语义类型"——你只关心"这是时间"，不关心它在底层是 $32$ 位还是 $64$ 位。

**代码示例**

```c
/* semantic_types.c — 语义类型示例 */
#include <stddef.h>
#include <stdint.h>
#include <stdio.h>

int main(void) {
    int arr[] = {1, 2, 3, 4, 5};

    size_t len = sizeof(arr) / sizeof(arr[0]);
    for (size_t i = 0; i < len; ++i)
        printf("%d ", arr[i]);
    printf("\n");

    ptrdiff_t diff = &arr[4] - &arr[0];
    printf("&arr[4] - &arr[0] = %td\n", diff);

    uint32_t ip = 0xC0A80001;
    printf("IP: %u.%u.%u.%u\n",
           ip >> 24, (ip >> 16) & 0xFF,
           (ip >> 8) & 0xFF, ip & 0xFF);
}
```

### 知识点 4：窄类型与整数提升

**是什么**

《Modern C》中将 Rank 小于 3 的类型称为窄类型

**详细解释**

根据基本类型表中的 Rank 列，`bool` `char`（以及 `signed/unsigned` 变体）、`short`（以及 `unsigned` 变体）都称为窄类型；它们无法直接参与运算

> [!TIP]
>
> 窄类型在参与任何运算之前，都会被编译器提升为 `int`（或者 `unsigned int`）；对于 $64$ 位平台，提升结果一定是 `int` 而不是 `unsigned int`

```c
unsigned char a = 200;
unsigned char b = 100;
int c = a + b; 			// a 和 b 先提升为 int，再相加，结果是 int 的 300
```

注意：`a` 和 `b` 本身还是 `unsigned char` 类，但是只要参与运算，编译器先把它们提升为 `int`，计算完得到的是 `int` 类型的值。这样会存在另一个问题，例如

```c
unsigned char a = 255;
unsigned char b = 1;
int c = a + b;       // 256，正常

unsigned char d = a + b;  // 256 塞不进 unsigned char，溢出！回绕为 0
```

> [!TIP]
>
> 参与算术运算的操作数至少应该是 `int` 类型的值，不要使用窄类型的值参与算术运算；它们应该只出现需要控制内存布局的场景。原因就是提升会让你以为在算窄类型，实际上在算 `int`，结果的行为和直觉不一致

**代码示例**

```c
/* narrow_promote.c — 窄类型提升演示 */
#include <stdio.h>

int main(void) {
    unsigned char a = 200;
    unsigned char b = 100;
    printf("a + b = %d (int 提升)\n", a + b);     // 300

    unsigned char c = a + b;
    printf("存回 char: %d (回绕)\n", c);          // 44

    printf("sizeof(a+b) = %zu (已是 int)\n", sizeof(a + b));
    printf("sizeof(a)   = %zu (仍是 char)\n", sizeof(a));

    bool x = 1, y = 1;
    printf("true + true = %d\n", x + y);           // 2
}
```

> `sizeof` 单纯的计算窄类型对象的大小不会进行整数提升

### 知识点 5：整数字面量

**是什么**

**字面量** 就是直接写在代码中的固定值。它不是变量，不是表达式，而是 **"字面上就是这个值"**。C 语言提供了多种方式来书写同一个值——就像人类可以用"42"、"四十二"、"XLII"表示同一个数字一样。


**详细解释**

C 标准规定了 $4$ 种形式的**整数字面值**，它们的表示形式如下表

| 进制              | 前缀 | 示例     | 值    | 说明                  |
| ----------------- | ---- | -------- | ----- | --------------------- |
| **十进制**        | 无   | `123`    | 123   | 最常用                |
| **八进制**        | `0`  | `077`    | 63    | 以 `0` 开头，历史遗留 |
| **十六进制**      | `0x` | `0xFFFF` | 65535 | 以 `0x` 开头          |
| **二进制（C23）** | `0b` | `0b1010` | 10    | 以 `0b` 开头          |

每个字面值都有一个 **类型**。对于整数类型的字面值，其类型推导遵循以下四条规则

+   规则一: 字面量永远非负

    ```c
    -34 // 不是"负三十四的字面量"
        // 而是"对字面量 34 做一元取负运算"
    ```

+   规则二: 十进制整数字面量是有符号的

    ```c
    1 // 类型：signed int（不是 unsigned int）
    ```

+   规则三: 十进制整数字面量取第一个能放下的有符号类型。三个有符号类型按 Rank 排列：`signed int → signed long → signed long long`。十进制字面量的类型是第一个能放下它的

    假设在某个平台上（`int` 类型占 $16$ 位）：

    | 字面量  | 值    | 放得进 `signed int`？ | 类型          |
    | ------- | ----- | --------------------- | ------------- |
    | `32767` | 32767 | ✅                     | `signed int`  |
    | `32768` | 32768 | ❌（超过 32767）       | `signed long` |
    
    在 $16$ 位 `int` 的平台上，`signed int` 的最小值是 $-32768$，但你无法用一个字面量直接表示它！因为：

    + `32768` 的类型是 `signed long`（放不进 `signed int`）
    + `-32768` 是对 `signed long` 字面量做取负运算，结果还是 `signed long`
    
+   规则四: 非十进制字面量的类型可以是有符号类型也可以是无符号类型。换句说，非十进制的字面的推导顺序为: `signed int → unsigned int → signed long → unsigned long → signed long long → unsigned long long`。例如，在一个 `int` 类型为 $16$ 位的平台上

    ```c
    0x7FFF      // 值 32767 → signed int（放得下）
    0x8000      // 值 32768 → unsigned int（放不进 signed int）
    0xFFFF      // 值 65535 → unsigned int
    ```

我们来看一个例子

```c
 int x = 0xFFFF'FFFF;
 // 你可能以为得到的是 -1（因为补码表示）
 // 但实际上 0xFFFF'FFFF 是 unsigned int，值为 4,294,967,295
 // 赋给 int 时发生窄化转换，结果是实现定义的
```

> [!TIP]
>
> 窄化转换是将尺寸更大类型的值转换为尺寸更小类型的值。窄化转换的行为是由实现定义
>
> + 保留最低有效位
> + 保留最高有效位
> + 直接拒绝编译
>
> 上述例子中如果能通过编译器，则变量 `x` 的值是未知的

C 标准规定了几个整数字面量后缀决定该字面量的具体类型

| 后缀                | 效果        | 示例   | 值   | 类型               |
| ------------------- | ----------- | ------ | ---- | ------------------ |
| `U` 或 `u`          | 强制无符号  | `1U`   | 1    | `unsigned`         |
| `L` 或 `l`          | 至少 `long` | `1L`   | 1    | `signed long`      |
| `LL` 或 `ll`        | `long long` | `1LL`  | 1    | `signed long long` |
| `WB` 或 `wb`（C23） | 精确位宽    | `42wb` | 42   | `_BitInt(N)`       |

后缀 `U` 或 `u` 可以与其他类型组合使用

| 后缀         | 示例    | 类型                 |
| ------------ | ------- | -------------------- |
| `UL`         | `1UL`   | `unsigned long`      |
| `ULL`        | `1ULL`  | `unsigned long long` |
| `UWB`（C23） | `42uwb` | 无符号 `_BitInt(N)`  |

**代码示例**

```c
/* integer_literals.c — 验证笔记中四条规则和陷阱 */
#include <stdio.h>

int main(void) {
    // 同一个值 42 的四种进制（验证笔记的表）
    printf("42      = %d (十进制)\n", 42);
    printf("052     = %d (八进制)\n", 052);
    printf("0x2A    = %d (十六进制)\n", 0x2A);
    printf("0b101010 = %d (二进制, C23)\n\n", 0b101010);

    // 规则一：字面量永远非负
    // -34 是对 34 取负，不是"负字面量"
    printf("sizeof(-34) = %zu (signed int)\n\n", sizeof(-34));

    // 规则二：十进制有符号 -> 规则三：第一个能放下的有符号类型
    printf("sizeof(42)      = %zu (int)\n", sizeof(42));
    printf("sizeof(2147483648) = %zu (long, 超出 int)\n",
           sizeof(2147483648));
    printf("\n");

    // 规则四：非十进制可无符号
    // 演示陷阱：0xFFFF'FFFF
    unsigned u = 0xFFFF'FFFF;
    printf("0xFFFF'FFFF as unsigned = %u\n", u);
    // 赋值给 int：窄化转换，行为由实现定义
    int x = 0xFFFF'FFFF;
    printf("0xFFFF'FFFF as int     = %d (窄化，值不确定)\n\n", x);

    // 后缀表验证
    printf("sizeof(1U)   = %zu (unsigned)\n", sizeof(1U));
    printf("sizeof(1L)   = %zu (long)\n", sizeof(1L));
    printf("sizeof(1LL)  = %zu (long long)\n", sizeof(1LL));
    printf("sizeof(1UL)  = %zu (unsigned long)\n", sizeof(1UL));
    printf("sizeof(1ULL) = %zu (unsigned long long)\n", sizeof(1ULL));
}
```

### 知识点 6：浮点和复浮点字面量

**是什么**

**字面量** 就是直接写在代码中的固定值。它不是变量，不是表达式，而是 **"字面上就是这个值"**。C 语言提供了多种方式来书写同一个值——就像人类可以用"42"、"四十二"、"XLII"表示同一个数字一样。

**详细解释**

C 标准规定了 $2$ 种浮点数字面值：十进制浮点数（小数形式和科学计数法形式）和十六进制浮点数。下表总结了 C 语言中这 $3$ 种浮点数字面值形式

| 形式         | 示例                | 解释                          |
| ------------ | ------------------- | ----------------------------- |
| 小数形式     | `3.14`, `.00007`    | 可省略前导零或尾部的零        |
| 科学记数法   | `1.7E-13`, `3.E+25` | $\text{mEe}= m \times 10^{e}$ |
| 十六进制浮点 | `0x1.7aP-13`        | $\text{hPe} = h \times 2^{e}$ |

小数形式是最常用的浮点数表示形式，其前导零或尾部零都可以省略；科学计数法形式也是小数形式的扩展

> [!WARNING]
>
> **陷阱**：小数形式的浮点字面量的实际值（对象的值）可能与你写的不同
>
> 因为浮点数在计算机中用二进制存储，但，**很大一部分十进制小数无法用二进制精确表示**。例如，$0.2$ 在我使用的机器上的实际值是 `0.200,000,000,000,000,011,1...` 这就像十进制中$\frac{1}{3} = 0.333\cdots$无法精确表示成小数一样；$0.2$ 的二进制表示也是无限循环小数：`0.2`（十进制）= `0.001100110011...`（二进制，无限循环）

小数形式的浮点字面量往往会带来一些令人以外的结果，例如

```c
0.2 == 0.2000000000000000111  // 可能为 true（两个不同写法的字面量，实际值相同）
```

为了解决这个问题，C 标准定义十六进制浮点字面量；它用于指定精确表示的浮点值；换句话说，**浮点数的十六进制表示与其二进制表示精确对应**，不会有舍入误差。

> 十六进制浮点字面量就是为了解决精度问题而设计的——**它能精确对应浮点数的二进制表示**

对于不同类型的 $0.2$，实际值也不同；因为它们的精度不同（32 位 vs 64 位 vs 80/128 位），舍入的位置也不同


|                    | `float`           | `double`                 | `long double`                |
| ------------------ | ----------------- | ------------------------ | ---------------------------- |
| 字面量             | `0.2F`            | `0.2`                    | `0.2L`                       |
| 实际值（十六进制） | `0x1.9999'9AP-3F` | `0x1.9999'9999'9999AP-3` | `0xC.CCCC'CCCC'CCCC'CCDP-6L` |

```c

0x1.9999'9AP-3   // 精确等于 1.60000002384 × 2⁻³ ≈ 0.20000000298
0xC.CCCC'CCCC'CCCC'CCDP-6  // 精确等于 12.8000000000000000002 × 2⁻⁶ ≈ 0.200000000000000000003
```

两个值非常接近，但十六进制写法看起来差异很大。这说明：十进制写法给人的直觉是错的——你以为 $0.2$ 就是精确的 $0.2$，但实际上它只是近似值

> [!TIP]
> 
> 同一个值（如 0.2）可以有不同的类型（float/double/long double），每种类型有不同的二进制表示，因此实际值也不同

默认情况下，浮点数字面值的类型是 `double` 而不是 `float`。可以使用浮点数字面值后缀强制指定类型

| 后缀       | 类型          | 示例   |
| ---------- | ------------- | ------ |
| 无后缀     | `double`      | `0.2`  |
| `f` 或 `F` | `float`       | `0.2F` |
| `l` 或 `L` | `long double` | `0.2L` |

C 通过 `_Complex` 关键字支持复数，标准库 `<complex.h>` 定义了虚数单位 `I`（虚数单位 $\sqrt{-1}$）

```c
#include <complex.h>
double _Complex z = 1.0 + 2.0 * I;
```

> 了解即可，需要是在查询相关内容

**代码示例**

```c
/* float_literals.c — 浮点字面量的精度陷阱和十六进制浮点 */
#include <stdio.h>

int main(void) {
    // 验证笔记中的精度问题：0.2 不能精确存储
    printf("0.2 = %.20f\n", 0.2);
    // 输出类似: 0.20000000000000001110（不是精确的 0.2）

    // 验证陷阱：0.2 == 0.2000000000000000111 居然为 true
    if (0.2 == 0.2000000000000000111)
        puts("0.2 == 0.2000000000000000111: true（精度陷阱）");

    // 十六进制浮点：精确定点，和二进制一一对应
    double d = 0x1.999999999999aP-3;
    printf("0x1.99...P-3 = %.20f\n", d);

    // 笔记中的表：同一值 0.2，不同类型精度不同
    float  f = 0.2f;       // 32 位
    double df = 0.2;        // 64 位
    long double ld = 0.2L;  // 80/128 位
    printf("float:       %a\n", f);    // %a 打印十六进制位模式
    printf("double:      %a\n", df);
    printf("long double: %La\n", ld);

    // 不同精度的 0.2 是否相等？
    printf("0.2f == 0.2 : %d\n", f == df);  // float 转 double 后可能不相等
}
```

### 知识点 7：字符和字符串字面量

**是什么**

字符字面量是放在 `'...'` 引号之间的**单个字符**，它的值由 C 标准隐式确定。字符串字面量是放在 `"..."` 引号之间的**字符序列**

**详细解释**

字符字面量将字符包围在单引号（`'...'`）之间，其类型是 `int`，而不是 `char`。`sizeof('a')` 的值应该是 $4$ 而非 $1$

字符 `\` 在字符字面量中存在特殊含义：用于表示无法直接输入的字符。由反斜杠 `\` 开头的字符字面量称为 **转义字符**。下表列出了几个常用的转义字符

| 转义 | 含义     | 转义 | 含义           |
| ---- | -------- | ---- | -------------- |
| `\n` | 换行     | `\f` | 换页           |
| `\r` | 回车     | `\\` | 反斜杠         |
| `\t` | 水平制表 | `\'` | 单引号         |
| `\v` | 垂直制表 | `\"` | 双引号         |
| `\a` | 响铃     | `\?` | 问好           |
| `\b` | 退格     | `\0` | 空字符（值 0） |

```c
'a'      // 字符 a 的整数值
'\n'     // 换行符
'\\'     // 反斜杠本身
'\0'     // 空字符，值为 0
'0'		 // 字符 0
```

字符串字面量将字符包围在双引号（`"..."`）之间，其类型是 `char[]`；也就是说，C 语言中的字符串本质上字符数组；为了确定字符串的结束位置，C 标准规定 `\0`（空字符）用于标记字符串的终止，因此，空字符 `\0` 也称为终止符

编译器如果如果发现了多个相邻的字符串字面量时会自动将它们拼接成一个字符串

```c
puts("first line\n"
     "second line\n"
     "third line");
// 等价于 puts("first line\nsecond line\nthird line");
```

> 这对写长字符串很有用——不需要一行写到底，可以分段写

> [!WARNING]
>
> 请特别注意：`'a'` 和 `"a"` 是完全不同的
>
> + `'a'` 是 `int` 类型的值，具体是多少取决于编译环境使用的字符集（例如，ASCII 字符集的值是 $97$）
> + `"a"` 是 `char[2]` 类型的值，包含了字符 `'a'` 和 字符 `'\0'`

**代码示例**

```c
/* char_string_literals.c — 字符和字符串字面量 */
#include <stdio.h>

int main(void) {
    // 字符字面量是 int，不是 char
    printf("sizeof('a')  = %zu (int!)\n", sizeof('a'));
    printf("sizeof(char) = %zu\n", sizeof(char));

    // 'a' 和 "a" 完全不同
    printf("'a'  = %d (int)\n", 'a');
    printf("\"a\"  = %zu 字节 (char[2]: 'a' + '\\0')\n", sizeof("a"));

    // '0' 和 '\\0' 截然不同
    printf("'0'  = %d\n", '0');    // ASCII 48
    printf("'\\0' = %d\n", '\0');  // 0

    // 字符串自动拼接
    printf("这三行会被"
           "编译器自动"
           "合并为一行\n");
}
```

### 知识点 8：隐式转换

**是什么**

计算机执行运算时，通常要求操作数具有相同的尺寸和表示方式；也就是说，操作数的类型必须相同才能执行运算。C 语言并没有这些要求，因为 C 编译器可以帮助我们统一运算符操作数的类型，这种由编译器完成的类型转换称为 **隐式类型转换**

**详细解释**

隐式类型转换中必须要理解的是算术转换，即运算符操作数类型不同是发生的转换。对于值运算符转换规则很简单

+ 规则一：执行整数提升，如果操作数类型统一，则类型转换完成
    + 补充：如果是一元运算符，结果类型就是整数提升后的操作数类型
+ 规则二：整数类型向浮点数类型转换，只要有一个操作数是浮点类型，另一个操作数就转换为浮点类型的值
+ 规则三：相同符号的整数类型按照 Rank 等级从低到高进行转换
+ 规则四：混合符号的整数类型转换规则比较复杂
    1. 相同 Rank 等级的有符号类型向无符号类型转换
    2. Rank 等级相差$1$ 时取决于平台
        1. `INT_WIDTH < LONG_WIDTH` 的平台上，`unsigned int` 的值被转换为 `signed long` 类型的值
        2. `INT_WIDTH == LONG_WIDTH` 的平台上，`signed long` 类型的值被转换为 `unsigned int` 类型的值

> [!WARNING]
>
> 总结：当有符号和无符号操作数混用时，隐式类型转换依赖于平台；因此，**避免混合有符号和无符号操作数**；能使用无符号就使用无符号

对于对象运算符，转换规则是固定的：右操作数转换左操作数（对象）类型的值。此外，调用函数时，转换规则也是固定的：实际参数转换为形式参数类型的值

```c
double       a = 1;              // 无害；值能放入类型
signed short b = -1;             // 无害；值能放入类型
signed int   c = 0x8000'0000;    // 危险；值太大，放不下类型
signed int   d = -0x8000'0000;   // 危险；值太大，放不下类型
signed int   e = -2'147'483'648; // 无害；值能放入类型
unsigned short g = 0x8000'0000;   // 丢失信息；值为 0
```



> [!WARNING]
>
> 对象运算符的左操作数(对象)的类型决定了整个表达式的类型；如果右操作数太大以至于无法放入左操作数，此时就会发生**窄化类型转换**。
>
> 窄化类型转换非常危险，应该禁止出现

**代码示例**

```c
/* implicit_convert.c — 隐式转换的陷阱和规则 */
#include <stdio.h>
#include <limits.h>

int main(void) {
    // 规则一：整数提升
    char a = 1, b = 2;
    printf("sizeof(a+b) = %zu (提升为 int)\n\n", sizeof(a + b));

    // 规则二：整数→浮点
    printf("1 + 0.0  : sizeof=%zu (double)\n", sizeof(1 + 0.0));
    printf("INT_MAX + 0.0F 可能丢失精度\n\n");

    // 规则三：相同符号向高 Rank 转 (1L→1LL)
    // 规则四：同 Rank 有符号→无符号 (1→1U)
    printf("sizeof(1U + 1)  = %zu (unsigned)\n", sizeof(1U + 1));
    printf("sizeof(1L + 1LL) = %zu (long long, 向高 Rank 转)\n\n", sizeof(1L + 1LL));

    // 教材的核心演示：混合符号性的危险
    printf("=== 混合 signed/unsigned 比较 ===\n");
    printf("-1 < 0   : %d (预期 true)\n", -1 < 0);
    printf("-1 < 0U  : %d (预期 true，实际 false! -1 被转成 UINT_MAX)\n", -1 < 0U);

    // 窄化转换陷阱
    unsigned u = 0x80000000;
    unsigned short g = u;   // 截断，只保留低 16 位
    printf("\n0x80000000 → unsigned short: %u (变成了 0)\n", g);

    // 一元 - 的类型
    printf("\n=== 一元 - 的类型 ===\n");
    printf("sizeof(-1)  = %zu (signed int)\n", sizeof(-1));
    printf("sizeof(-1U) = %zu (unsigned, 值是 UINT_MAX)\n", sizeof(-1U));
}
```

### 知识点 9：初始化器

**是什么**

初始化器在对象定义是为其提供初始值。对于聚合对象使用 `{...}` 形式的初始化器，对于标量对象可以直接使用表达式。从 C23 开始，花括号形式的初始化器适用于所有类型的对象

**详细解释**

一个未初始化的变量，值是不确定的，这往往是 bug 出现根源。因此，《Modern C》从开始就强调

> [!TIP]
>
> 所有变量都应该被初始化。 唯一的例外是需要极致优化的热点代码，而现代编译器会把多余的初始化优化掉，所以大胆写就行。

C 语言中的基本类型都是 **标量** 类型，直接使用一个表达式初始化——表达式值自动转成目标类型。注意，不要出现窄化类型转换情形

```c
double a = 7.8;
double b = 2 * a;
double c = { 7.8 };     // {} 可加可不加
double d = { 0 };
```

数组是我们已经见过的聚合类型，虽然还没有正式学习。现在，我们提前学习数组的初始化器。直接看例子

```c
double A[] = { 7.8, };          	 // 一个元素，类型由初始化器确定长度
double B[3] = { 2 * A[0], 7, 33, };  // 三个元素，末尾逗号合法
double C[] = { [0] = 6, [3] = 1, };  // 指定初始化器：C[0]=6, C[1]=0, C[2]=0, C[3]=1
```

1. `double A[]` 声明时没有提供数组的长度，对于数组而言，这是不完整的。这种情况下，必须提供初始化器，以便于编译器可以从初始化器中推导数组的长度
2. `double B[3] = { 2 * A[0], 7, 33, };` 形式的初始化称为顺序初始化。初始化器末尾的逗号（`,`）是合法的，不必删除。保留它可以方便后续增加初始器中的元素
3. `double C[] = { [0] = 6, [3] = 1, };` 形式的初始化器称为指定初始化器。它明确定义了那个位置放置什么值，未指定的自动填充 $0$

> [!TIP]
>
> 对所有聚合类型，优先用指定初始化器。它比按位置填更健壮——增删元素不会导致数据错位

4. C23 引入了**通用默认初始化器** `{}`：

```c
double D[100] = { };   // C23：全部初始化为 0
int    x     = { };    // C23 标量也可以
```

> C23 之前只能写 `{0}`。`{}` 统一了所有类型的默认初始化——所有位清零。

**代码示例**

```c
/* initializers.c — 三种初始化方式和 C23 默认初始化器 */
#include <stdio.h>

int main(void) {
    // 标量初始化：表达式自动转换
    double a = 7.8;
    double b = 2 * a;

    // 顺序初始化
    double B[3] = { 2 * a, 7.0, 33.0, };
    for (size_t i = 0; i < 3; ++i)
        printf("B[%zu] = %.1f\n", i, B[i]);

    // 指定初始化器：未指定的自动填 0
    double C[] = { [0] = 6.0, [3] = 1.0, };
    printf("C 的长度: %zu\n", sizeof(C) / sizeof(C[0]));
    for (size_t i = 0; i < 4; ++i)
        printf("C[%zu] = %.1f\n", i, C[i]);

    // C23 通用默认初始化器
    int x = { };
    double D[5] = { };
    printf("x = %d\n", x);               // 0
    printf("D[2] = %.1f\n", D[2]);        // 0.0
}
```
