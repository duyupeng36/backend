# 快速入门

C 语言是一种**通用编程语言**，由 Dennis Ritchie 于 1970 年代初在贝尔实验室创建。它能够**直接访问内存和硬件**，同时**贴近机器本身**，这使其既快速又可预测，但也要求程序员承担更多责任。操作系统、嵌入式固件、编译器以及许多其他语言的运行时都是使用 C 构建的；这些程序的共同特点：**以最小开销贴近硬件运行时**。

> [!TIP]
>
> 学习 C 能让人理解计算机实际如何管理内存和执行指令，这些知识几乎可以迁移到所有其他语言中

从技术上讲，计算机只能识别并执行由**位序列**表示的**指令**：即，由 $0$ 或 $1$ 组成的序列，也称为 **二进制指令** 或 **机器指令**。直接使用二进制指令编写程序是非常困难且不易实现的，因此，计算机科学家们发明了一套 **符号助记符** 用于表示二进制指令，这套符号助记符就称为 **汇编语言**

> [!TIP]
>
> 使用汇编语言编写的程序本质上就是一个文本文件，它无法被计算机理解。我们需要使用另一个称为 **汇编器** 的特定程序将汇编程序翻译为机器指令

**汇编语言也是与特定指令集体系结构绑定的**。使用汇编语言编写的程序只能在特定体系结构的计算机上执行，即 **汇编语言不具备可移植性**，一旦更换不同指令集体系结构的计算机就需要使用汇编语言重新编写程序。C 语言为所有不同的体系结构的汇编语言提供了一个抽象级；**正确的 C 程序在不同的平台之间是可移植的**

> [!TIP]
>
> C 语言编写的程序文本表示我们希望计算机做什么；同样，也只是我们编写的另一个文本文件。我们需要使用 **编译器** 将 C 程序翻译为汇编指令，然后再用汇编器将汇编指令翻译为机器指令。

我们将 **编译器** 和 **汇编器** 统称为编译器。目前市面上存在很多编译器；使用最为广泛的便是 [GCC](https://gcc.gnu.org/) 和 [Clang + LLVM](https://clang.llvm.org/)。下面我们将安装编译器和编辑器，并配置 C 语言开发环境

## 开发环境搭建

目前我正在使用的是 Windows11 操作系统；但是，后续我们需要在 Linux 系统上开发和工作；因此，我们选择 WSL(Windows Subsystem for Linux) 作为开发环境

```pwsh
<# 1. 查看 WSL 支持的各个发行版。目前 WSL 支持 Ubuntu Debian AlmaLinux archlinux 等发行版 #>
wsl --list --online

<# 2. 安装 Linux 子系统：对于初学者，推荐选择 Ubuntu 或 archlinux; 当然，也可以选择自己属性的发行版 #>
wsl --install Ubuntu
```

等安装完成之后，我们还需要为 WSL 添加一些配置：

```ini
[wsl2]
memory=24GB  # 限制 WSL2 虚拟机最大可用内存为 24GB。默认是 50%
networkingMode=Mirrored # 镜像网络模式。WSL 与 Windows 共享同一个网络
vmIdleTimeout=-1    # WSL 虚拟机空闲时不自动关闭

[experimental]
hostAddressLoopback=true # 启用 Windows→WSL 的回环地址访问

[general]
instanceIdleTimeout=-1 # 控制实例级别的空闲超时。-1 表示不超时
```

> [!NOTE]
>
> 这个配置的核心意图是让 WSL 保持常驻运行 + 网络与 Windows 无缝互通，适合长期开发使用

WSL 配置完成，现在需要安装 GCC 和 Clang + LLVM 以配置开发环境

```shell
# 1. 安装编译工具集合：make gcc/g++ libc/libc++ 等
➜ sudo apt install build-essential 
➜ sudo apt install cmake gcc-16 g++-16 gdb 
➜ sudo apt install clang-22 llvm-22 lld
# 2. 安装 clangd：代码提示工具
➜ sudo apt install clangd-22
```

编译器安装完成之后，我们还需要一个文本编辑器来编写 C 语言代码。[visual studio code](https://code.visualstudio.com/) 是我们首选的编辑器，它支持各种插件，可以配置成任何开发环境。并且，vscode 还支持不同的操作系统。

我们只需要安装 Winodws 版本的 vscode；然后安装以下插件

+ WSL: 用于远程连接 WSL
+ C/C++ Extension Pack: 包含了 C/C++ 开发的所有插件
+ clangd: 用于 C/C++ 代码的智能感知引擎，提供代码提示

clangd 可能与C/C++ 插件的智能感知引擎发生冲突，我们需要将 C/C++ 插件的智能感知引擎禁用

```json
{
    "C_Cpp.intelliSenseEngine": "disabled",
}
```

在项目的根目录下添加 `.clangd` 文件，并插入下面的内容：`clangd` 可以根据后缀名使用不同的编译器和不同的选项

```clangd
If:
  PathMatch: [".*\\.c$"]
CompileFlags:
  Add: ["-std=c23"]

---
If:
  PathMatch: [".*\\.cpp$"]
CompileFlags:
  Add: ["-std=c++23", "-stdlib=libc++", "-fmodule-file=std.pcm"]  
```

> [!NOTE]
>
> 我们选择使用 Clang+LLVM 作为我们学习过程中使用的编译器。

## 第一个 C 程序

学习编程语言的唯一方法就是使用它编写程序。C 程序对形式化的东西要求较少，一个完整的 C 程序往往只需要寥寥数行即可。例如，下面这个名为 [pun.c](../../02-practice/modern-c/pun.c) 的程序在每次运行时都会输出一串消息：`"To C, or not to C: that is the question."`

```c
/* pun.c - 第一个完整的 C 程序：输出双关语 */
#include <stdio.h>  // 包含标准输入/输出库

// main 函数定义：程序的可执行代码
int main(void) {
  // 调用函数 printf（来自标准输入/输出库）：输出格式化后的文本到屏幕
  printf("To C, or not to C: that is the question.\n");
  return 0; // 返回 0 表示程序正常结束
}
```

在我的计算机上，此程序运行的结果为

```shell
➜ ./pun
To C, or not to C: that is the question.
```

程序 [pun.c](../../02-practice/modern-c/pun.c) 中可以很容易找到程序输出的文本：第 7 行引号之间的部分。实际输出动作由第 7 行的函数调用 **语句** 完成：语句 `printf("To C, or not to C: that is the question.\n")` 调用了一个名为 `printf` 的**函数**；这里，`printf` 函数接收 $1$ 个参数，包含在一对括号 `(....)` 中

> [!NOTE]
>
> `printf` 函数可以产生完美的格式化输出，我们将在 [格式化输入输出](./格式化输入输出.md) 中介绍

## 编译和运行

程序文本只是表示我们希望计算机执行的动作。它只是我们写的**另一段文本**，并存储在硬盘的某处，但程序文本本身无法被你的计算机所理解。有一个叫做 **编译器** 特殊的程序，它将 C 程序文本翻译为机器可以理解的 **二进制代码** 或 **可执行文件**

> [!NOTE]
>
> 编译器非常复杂，目前而言，我们不需要深入理解，只需要知道如何使用这个工具并了解编译器翻译程序的流程即可

如何使用编译器取决于运行程序的目标平台：开始我们就说过，二进制代码依赖于平台，它的形式和细节取决于要运行它的计算机。C 语言只是为不同机器的特定语言提供了一个抽象级

> [!TIP]
>
> **正确的 C 程序可以在不同平台之间是可移植的**。我们会花费大量的时间来学习如何编写一个正确的 C 程序

前面我们已经安装 Clang 和 GCC，我们建议使用 GCC 作为学习使用的编译器。我们可以像下面的方式使用 GCC 编译器

```shell
➜ gcc -std=c23 -Wall -Wextra -Werror -g 02-practice/modern-c/pun.c -o build/bin/pun
```

编译器应该毫无怨言地完成它的工作，并将可执行文件输出到当前目录下的 `./build/bin/` 目录中

+ `-std=c23` 指示编译器使用 C23 标准进行编译
+ `-Wall -Wextra` 指示编译器发现任何不寻常的事情并发起告警
+ `-Werror` 使用严格模式：任何不寻常的事情都当作错误处理
+ `-g` 指示编译器生成调试信息
+ `-o build/bin/pun` 告诉编译器输出文件的目录
+ `02-practice/modern-c/pun.c` 指明 **源文件**，该文件包含我们编写的 C 代码

现在，我们可以执行这个新创建的程序了

```shell
➜ ./build/bin/pun 
To C, or not to C: that is the question.
```

这个程序在任何平台使用任何编译器得到的可执行程序最终的输出应该是完全一致的

> [!NOTE]
>
> 可移植的含义：无论在何处编译并运行程序，其**行为**应该是一样的

## 诊断信息

下面我来看一个有缺陷的示例代码

```c
/* bad-pun.c - 有缺陷的 C 程序：演示编译器的告警 */

// main 函数定义：程序的可执行代码
void main(void) {
  // 调用函数 printf（来自标准输入/输出库）：输出格式化后的文本到屏幕
  printf("To C, or not to C: that is the question.\n")
  return 0; // 返回 0 表示程序正常结束
}
```

当我们试图编译这个程序时，编译器会发出许多告警信息

```shell
➜ clang -std=c23 -Wall -Wextra -Werror -g 02-practice/modern-c/bad-pun.c -o build/bin/bad-pun
02-practice/modern-c/bad-pun.c:4:1: error: 'main' must return 'int'
    4 | void main(void) {
      | ^~~~
      | int
02-practice/modern-c/bad-pun.c:6:3: error: call to undeclared library function
      'printf' with type 'int (const char *, ...)'; ISO C99 and later do not
      support implicit function declarations [-Wimplicit-function-declaration]
    6 |   printf("To C, or not to C: that is the question.\n")
      |   ^
02-practice/modern-c/bad-pun.c:6:3: note: include the header <stdio.h> or
      explicitly provide a declaration for 'printf'
02-practice/modern-c/bad-pun.c:6:55: error: expected ';' after expression
    6 |   printf("To C, or not to C: that is the question.\n")
      |                                                       ^
      |                                                       ;
02-practice/modern-c/bad-pun.c:7:3: error: void function 'main' should not return
      a value [-Wreturn-mismatch]
    7 |   return 0; // 返回 0 表示程序正常结束
      |   ^      ~
4 errors generated.
```

> [!NOTE]
>
> 这些告警信息提示我们应该如何修改程序
>
> + `error: 'main' must return 'int'`: 函数 `main` 的返回类型必须时 `int`
> + `error: call to undeclared library function`: 调用 `printf` 函数时，编译器不知道它是一个函数
> + `error: expected ';' after expression`: 语句缺少分号作为结束标记
> + `error: void function 'main' should not return`: 函数 `main` 的返回类型声明为 `void` 但是却提供了返回值

按照上述诊断信息，我们可以快速将程序修复

```c
/* pun.c - 第一个完整的 C 程序：输出双关语 */
#include <stdio.h> // ⬅ 引入标准输入/输出库头文件，提供 printf 函数的声明

// main 函数定义：程序的可执行代码
int main(void) { // ⬅ 返回类型 void → int
  // 调用函数 printf（来自标准输入/输出库）：输出格式化后的文本到屏幕
  printf("To C, or not to C: that is the question.\n"); // ⬅ 补充分号
  return 0;
}
```

现在编译该程序，就不会有诊断信息了。编译器帮助我们找出程序行中出现问题的行，如果有一点经验，你将能够理解它所告之的含义。**一个好的C程序应该在没有告警的情况下干净地编译**
